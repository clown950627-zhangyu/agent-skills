## 二、⭐ 歌词同步（最重要·必守铁律）

**必须用 Whisper 词级时间戳**，严禁估算：

```python
from faster_whisper import WhisperModel
model = WhisperModel("small", device="cpu", compute_type="int8")
segments, _ = model.transcribe(wav, language="zh", beam_size=5, word_timestamps=True)
```

- 踩坤实录：按"每句6.5秒"估算 → 歌曲实际每句3-4秒 → **越到后面越错**（用户一眼看出）
- 字幕显示时间 = 歌曲时间 − AUDIO_START + DELAY_MS/1000
- 抽帧验证：在每句字幕**中间时刻**抽帧 + RapidOCR 核对

### Whisper 报 `metadata_errors` 时：先转 wav 再喂 numpy 数组

`av` 与 faster-whisper 版本不匹配时报 `TypeError: open() got an unexpected keyword argument 'metadata_errors'`——
这是**解码层**的问题，不是模型、不是音频有问题（同一条命令改成喂数组就好）。

```
ffmpeg -i in.mp3 -ac 1 -ar 16000 -f wav /tmp/a.wav          # 先转 16k 单声道
wave → np.frombuffer(readframes, int16).astype(float32)/32768.0
model.transcribe(数组, language="zh", word_timestamps=True)   # 不传文件路径，绕开 av 解码
```

### ⭐⭐ 歌词文本必须核对原稿（血泪教训·2026-09-24）
**Whisper 只用来定时间轴，歌词文本必须以原歌词为准！**
- 事故：把副歌里的一句写成了同一首歌**另一段落**的歌词（"风有风的方向" vs 实际"风来风就走 云飘云就飘"）→ 用户发现"倒数第二句歌词不对"
- 正确做法：
  1. 先找**原歌词**（Suno歌词海报截图 / 素材包 md / 歌手提供）
  2. Whisper 转录结果只用来对齐时间，**文字要逐字核对原稿**
  3. 转录与歌词不符时（尤其识别成"风来风流走"这类乱码）→ **不要猜**，找原稿或问用户

### ⭐ 选段落前先看能量曲线
- 用每秒能量（0.5秒hop）找**自然停顿点**（能量<0.05处）作为段落边界
- 事故：选了 104.5-136秒，但副歌实际在 51.4-77.1秒（76秒有停顿）→ 切在歌中间 → "副歌不完整"
- 流程：先扫能量找停顿 → 再确认该段落首尾句 → 才定 AUDIO_START/LEN

## 五·五、实拍场景 MV（用户扔一张门店/街景照就要片子）

最近越来越多是「用这张照片做个视频，配我的歌副歌，高级」。这种片子只需一张图，靠运镜和字撑。

```
画面   ★ 不要裁原图（用户反馈：「画面为什么被你缩放了？保持原来的图」）
       默认做法：毛玻璃垫底 + 原图完整居中，一个像素不改
       底：scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,gblur=sigma=40,eq=brightness=-0.10
       前：scale=1080:-2 居中 overlay
       + 慢推 zoompan=z='min(zoom+0.00045,1.08)'（37 秒也只推 8%，太快像手抖）
       只有用户明确说「要满屏」才用单图 crop；裁完再交大概率被打回，招牌/边角没了他一眼看出来
调色   夜景原片偏暗：brightness=0.07:gamma=1.14:saturation=1.10 提亮保色
       ❌ 不要再叠加色调的暗角/降饱和，门店的暖光就是氛围
字幕   ★ 位置改 0.62H，不用 0.47H——实景照中部是招牌/门框，0.47H 正好压在字上
       （0.47H 只适用于 AI 生成的空旷大场景）
片头   �奶油色衬线大字 + 一行小字「楼上用户 · 演唱版」+ 一条砖红细线（#A33B2C）
结尾   门头场景的短句走「灯/路/人」这一路（如「灯亮着，路就在脚下」），不用「慢慢走不必慌张」
```

**一张图撑 30+ 秒的关键是「别让人看见它没动」**：全程 3–8% 的缓推 + 字幕逐句换行，
节奏来自歌词而不是切镜头。不要为了「有变化」加推拉往返，用户的第一个反馈就是「晃动」。

### 时间轴优先复用项目里已存的词级时间戳

做过的歌，`MV_<歌名>_抖音/` 下往往已经有 `chorus_words.json`（逐词 `[绝对秒, 字]`）
和切好的 `chorusM.wav`。**直接读它，不要重跑 ASR**——省两三分钟，也少一次认错字。
注意时间基准是整首歌的绝对秒数：用前先减切片起点（如 `62.0`），否则字幕全提前。

分组句子时按词级时间手写句首尾，不要信任空白字符分组（中文歌词里空格不规律，
按空格切出来的行会一条条跟实际断句对不上）。

## 八、技术坑（必避·全是血泪）

1. **`overlay` 必须加 `-t {时长}` + `shortest=1`** — 否则无限渲染·文件膨胀到 826MB
2. **单图/结尾帧用 `-frames:v N` 限制** — 不要把 `-t` 放在 `-i` 前面（会导致 zoompan 无限输出→100秒）
3. **字幕 PNG 裁条状**（y=560~760）— 全屏 PNG overlay 极慢（20分钟跑不完）
4. **字幕句数用 `len(LYRICS)`** — 不要写死数字（否则 overlay 报错 234）
5. ffmpeg 滤镜里的中文逗号/英文单引号会崩 → 用 PNG 叠加（最稳）
6. 视频总长 ≥ 音频长度 + 0.3秒（否则最后一句被切）
7. 高分辨率（2048）图片做 zoompan 会慢 → 先 scale 到 1620×2880 再 zoompan
